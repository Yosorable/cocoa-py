# 0.1.0a9

This release adds compact sprite batches, reduces Scene traversal and drawing
overhead, and reuses audio playback resources while preserving their lifecycle.
All modules retain their independent top-level imports.

## Scene

- `SpriteBatch` stores many image records in one node. `BatchSprite` handles
  support individual edits, while `set_transforms`, `set_poses` and
  `update_sprites` validate and copy whole updates before committing them.
  Parent records preserve transforms, visibility, opacity and clipping;
  ordinary depth sorting, cached Layers and capture remain supported.
- Batch storage and drawing caches participate in cyclic garbage collection.
  Rendering retains their owners until commands have been packed and rejects
  edits or recursive collection during callbacks, including texture finalizers.
  Dynamic record clips invalidate stationary frames.
- `Node.affine_transform` accepts a finite six-coefficient matrix before the
  component transform. Layout and capture account for the composed matrix.
- `gpu.Frame.draw_many` submits ordered draw entries through one native call.
  Texture, blend and clip changes still follow the existing batching rules;
  a `SpriteBatch` does not guarantee a single GPU draw call.
- Node updates and UI registry scans use native traversal while preserving
  Python callbacks, child snapshots and inherited speed. The initial requested
  Scene frame-rate limit now reaches the native window.

See the [API guide](../api.md) for signatures, clipping coordinates and ownership.
Animation selection and application state remain in Python.

## Audio

Compatible completed PCM voices use a bounded cache. Natural completion keeps
the player and rate-processing state continuous; explicit stop cancels playback
and resets reusable processing state. File streams keep their independent
lifecycle, and channel controls remain isolated between uses.

Coupled playback rate and pitch use resampling, while independent changes retain
time stretching. Live playback and offline rendering use the same selection.
Pause and seek requests made during asynchronous loading are preserved, and
playback can restart the engine after recording stops.

## Build and distribution

The iOS builder accepts `--no-isolation` to reuse installed build dependencies.
Metal module caches live in the separate device and simulator build directories.

The `v0.1.0a9` tag identifies the release source. Distribution files are:

- `cocoa_py-0.1.0a9-cp314-cp314-macosx_14_0_arm64.whl`
- `cocoa_py-0.1.0a9-cp314-cp314-ios_17_0_arm64_iphoneos.whl`
- `cocoa_py-0.1.0a9-cp314-cp314-ios_17_0_arm64_iphonesimulator.whl`
- `cocoa_py-0.1.0a9.tar.gz`

Minimum targets remain macOS 14+ and iOS 17+, with standard GIL-enabled
CPython 3.14. The simulator wheel targets Apple Silicon Macs.

## Validation

The release wheel was tested with CPython 3.14.6 on Apple Silicon macOS
26.6.2 and Xcode 27.0. The suite with desktop UI enabled completed 453 tests:
449 passed and four were skipped. The passing tests include all 310 Scene tests
and live audio playback coverage. Three skipped iOS artifact tests were then run for each
iOS wheel; the network geocoder test remained disabled. Each iOS wheel passed
all four platform, architecture, linkage, shader, resource and RECORD checks.

The maintainer also reported no substantial issues in manual phone testing of
a local candidate with the same runtime sources. This is separate from the
automated macOS and artifact checks. No automated device or Simulator runtime
suite was rerun, and the declared minimum OS versions were not tested separately.
