# 0.1.0a6

This release gives `device`, `location`, `motion`, `clipboard` and `share`
explicit parameter types and typed results. It also removes the `notification`
module that was present in 0.1.0a5.

## System APIs

- Device information, battery and storage results, location status, motion
  capabilities and samples, and stream statistics use immutable dataclasses.
  Optional measurements allow `None`; unsupported platform capabilities remain
  explicit in the result or raise `NotImplementedError` when requested.
- Location and motion watch factories expose their keyword arguments directly.
  Motion factories and constructors infer the sample type from the sensor name.
  Requests, streams, iteration and context managers preserve their result types.
- Paths, buffers, images and string choices have explicit input types.
  `clipboard.read_image(as_bytes=True)` is typed separately from Pillow output.
  Importing the wrappers and inspecting their signatures does not import Pillow
  or NumPy.
- Clipboard representations and share attachments remain mappings because their
  keys are supplied by the caller. Fixed records are defined by the native
  adapters across platforms, rather than exposing arbitrary system metadata.
- Companion stub packages and `_cocoa/py.typed` ship in all wheels and are copied
  by the optional source-based embedded installer. Generated public declarations
  are checked against the inline annotations.

## Migration

Replace dictionary indexing on fixed results with attribute access, for example
`device.battery()["level"]` becomes `device.battery().level`, and
`watch.stats["dropped"]` becomes `watch.stats.dropped`. Use
`dataclasses.asdict(result)` when a dictionary is needed. Motion samples expose
nested `Vector3`, `Attitude` and `Quaternion` records. See
[system module types](../typing.md) for the result types and examples.

The `notification` module, its native implementation and the launcher's
notification integration have been removed. Applications using that alpha API
must remove those imports or provide notification integration in their host.

## Validation

Release builds use CPython 3.14.6 on Apple Silicon macOS 26.6.2 and Xcode 27.0.
The macOS regression run completed 353 tests: 191 passed and 162 optional or
environment-dependent cases were skipped. Installed-package checks cover both
mypy and Pyright inference and rejection of invalid calls. Device and simulator
wheel validation each passed all four tests, including native platform,
architecture, linkage, resources and RECORD hashes.

Runtime validation on an iOS 26.5 simulator with CPython 3.14.7 passed all 37
checks for the five system modules. These cover typed results, clipboard
round trips, location authorization states and simulated updates, public-address
geocoding, and sharing presentation, cancellation, timeout and cleanup. Sharing
success and error paths use controlled completion callbacks; no content is sent
to an external service. Motion and compass checks cover unavailable hardware
and native queue decoding with injected samples, not physical sensor readings.
Geocoding remains provider-dependent; the regional provider returned no result
for one US reverse-geocoding coordinate and passed the China reference cases.

The minimum supported macOS and iOS versions were not run separately. Physical
sensor behavior and real sharing destinations still require device checks.
