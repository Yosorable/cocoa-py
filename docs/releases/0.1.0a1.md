# 0.1.0a1 release validation

## Scope

The first preview provides only the top-level `coreml` native extension. The
existing CoreML implementation was copied unchanged from Pythona for standalone
builds. Other app source files and the Pythona runtime are not included. Other
modules and iOS host integration have not yet been migrated.

## Completed checks

- Built the source distribution and wheel on macOS 26.6.2, Apple Silicon, with
  standard CPython 3.14.
- Used setuptools 84.0.0 and NumPy 2.5.3 in isolated build environments.
- Built the wheel from the generated source distribution and verified that the
  source archive includes native headers and test models.
- Installed the wheel in a separate virtual environment and confirmed that
  `coreml` loads from that environment's site-packages.
- Passed all nine public API regression tests, covering real Core ML model
  compilation and inference, RGB/RGBA, grayscale and Float16 data, noncontiguous
  arrays, batch inference, model descriptions, paths, and invalid arguments.
- Confirmed that the wheel does not expose internal test-only interfaces.
- Passed `twine check --strict` for both release files.
- Confirmed with `vtool` that the extension targets macOS 14.0 or later, and with
  `otool` that it links only Apple system libraries.
- No simulator was used. Execution on the minimum supported macOS version has
  not yet been verified on a separate older system.

## Publication results

Published to production PyPI on 2026-09-12 (UTC+8), maintained by `Yosorable`:
[cocoa-py 0.1.0a1](https://pypi.org/project/cocoa-py/0.1.0a1/).

- PyPI accepted the source distribution and macOS ARM64 wheel, confirming that
  the `cocoa-py` project was created successfully.
- Downloaded both files from PyPI. Their SHA-256 hashes match the PyPI JSON
  metadata and the local build artifacts.
- Installed `cocoa-py[coreml]==0.1.0a1` from production PyPI in another fresh
  virtual environment. The native `coreml` extension and NumPy 2.5.3 imported
  successfully, with the expected package version and public API.
- The source repository is [Yosorable/cocoa-py](https://github.com/Yosorable/cocoa-py).

The upload used `twine upload --config-file ~/.pypirc --repository pypi`.
In Twine 7, `--repository-url` bypasses account settings in `.pypirc`; selecting
the configured repository by name allows Twine to read those credentials.
Publishing credentials were kept in the user's `~/.pypirc` and were not included
in Git or either release file.
