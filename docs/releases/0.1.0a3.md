# 0.1.0a3

This release fixes stale rendering for subclasses of scene shapes. Changing a
stationary custom button's fill now updates its appearance on the next frame;
moving the node or camera is no longer necessary to see the selected state.

## Changes

Custom nodes use Python `_emit()` and `_snap()` methods. The native collector
previously excluded their negative type identifier from snapshot validation,
so it could reuse old drawing commands after a style or geometry change.
The collector now checks custom snapshots and saves them after emission.
Unchanged nodes retain command caching and static frame skipping, and subclass
rendering overrides continue to run through the Python fallback.

The regression suite covers repeated button color toggles without movement,
shape subclass size changes, custom snapshot state and static frame reuse.
The Pythona user reported successful on-device validation of the affected
Audio + Camera example after testing the fix. No example changes are required.

## Distribution

The `v0.1.0a3` Git tag identifies the release source. The release contains:

- `cocoa_py-0.1.0a3-cp314-cp314-macosx_14_0_arm64.whl`
- `cocoa_py-0.1.0a3-cp314-cp314-ios_17_0_arm64_iphoneos.whl`
- `cocoa_py-0.1.0a3.tar.gz`

Platform requirements and public APIs remain as documented for
[0.1.0a2](0.1.0a2.md). Automated checks use Apple Silicon macOS with CPython 3.14,
native Metal, and iPhoneOS artifact inspection; the host application is also
built for arm64 iPhoneOS. Simulator execution and unrelated device permissions
or audio routes are outside this fix's validation scope.
