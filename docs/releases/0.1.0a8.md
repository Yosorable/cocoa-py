# 0.1.0a8

This release adds Scene pointer input and window controls, corrects sprite and
particle rendering, and keeps location availability queries off the UI thread.
The distribution retains its independent top-level modules and synchronous
Python location APIs.

## Scene input and windows

- Scenes receive immutable `PointerEvent` values through `pointer_moved` and
  `pointer_exited`, with the latest hover position in `pointer_position`.
  Losing input ownership cancels hover. Consecutive moves never coalesce across
  touch, key or scroll events, preserving the position seen by each callback.
- `Touch.button` and `Touch.source` distinguish pointer buttons, direct contact
  and Pencil input. Secondary contacts reach scene callbacks without activating
  standard scene controls.
- `Scene.scroll` receives `ScrollEvent` deltas left after nested scroll views
  consume their portions. See [pointer input](../scene-pointer-input.md).
- `TextField`, `TextView` and `TextInputSession` support `on_cancel` after Escape
  ends editing. Text remains intact, and active input-method composition retains
  ownership of Escape. See [text input](../scene-text-input.md).
- `Scene.fullscreen` and `gpu.Window.fullscreen` expose native macOS fullscreen
  state and transitions. UIKit presentation continues to belong to the host.
  See [macOS execution](../macos.md#fullscreen-presentation).

## Rendering

Sprites retain the full inherited affine transform, including shear and
reflection, in both native and Python rendering paths. `SpriteFrame` is exported
for callers with texture-region metadata. Existing collision approximations are
unchanged; see [sprite transforms](../scene-sprite-transforms.md).

Sprite and particle `blend` values now select the corresponding Metal pipeline.
Both alpha and additive blending preserve alpha coverage for transparent capture,
and changing a sprite's blend mode invalidates cached commands. Textured particles
no longer multiply already-premultiplied texture RGB by the texture alpha again.

`ParticleEmitter` now defaults to `blend="alpha"`, matching `Sprite`. Choose
`blend="additive"` explicitly for glowing effects such as sparks or fireworks.
Code that previously set a particle blend mode that was ignored will now see
that mode take effect. Low-level callers can select
`gpu.Pipeline(..., blend_mode="additive")`.

## Location

Location Services availability checks run on a background queue. Manager
creation, authorization and delegate callbacks remain on the main run loop.
`location.status()`, location fixes and location-dependent compass requests keep
their synchronous Python interfaces without blocking the UI on the services query.

Completion uses the main run loop, allowing synchronous calls made inside a
task on the main queue to finish. Cancellation during the check prevents late
completion from starting a manager or requesting permission. Native exceptions
in the asynchronous query and startup paths become Python errors.

## Distribution and validation

The `v0.1.0a8` tag identifies the release source. Distribution files are:

- `cocoa_py-0.1.0a8-cp314-cp314-macosx_14_0_arm64.whl`
- `cocoa_py-0.1.0a8-cp314-cp314-ios_17_0_arm64_iphoneos.whl`
- `cocoa_py-0.1.0a8-cp314-cp314-ios_17_0_arm64_iphonesimulator.whl`
- `cocoa_py-0.1.0a8.tar.gz`

The minimum targets remain macOS 14+ and iOS 17+, with standard GIL-enabled
CPython 3.14. The simulator wheel targets Apple Silicon Macs.

Validation uses CPython 3.14.6 on Apple Silicon macOS 26.6.2 and Xcode 27.0.
The standard macOS run completed 381 tests: 206 passed and 175 optional or
environment-dependent tests were skipped. A separate run with desktop UI enabled
passed all 249 Scene tests. The 26 location tests cover delayed queries, main
loop responsiveness, cancellation, exceptions and synchronous calls from the
main queue. Both iOS wheels passed all four platform, architecture, linkage,
resource and RECORD checks.

The iOS runtime was also exercised on an iPhone 18 Pro Max simulator running
iOS 27.0 using the preceding local candidate. Its native extensions, Python
wrappers and shader resources match the release wheels. Two Pythona integration
tests covered framework imports, metadata, resources, location status and
particle blending. The earlier Core Location main-thread performance diagnostic
did not recur. The iPhoneOS Debug host build also passed with App signing disabled.

The minimum supported macOS and iOS versions were not run separately. No physical
iPhone was used; real sensors, permission decisions and hardware routing remain
device checks.
