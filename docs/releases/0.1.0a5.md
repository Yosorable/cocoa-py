# 0.1.0a5

This release adds an arm64 iOS Simulator wheel alongside the existing macOS and
iPhoneOS wheels. Public Python APIs remain unchanged.

## Simulator packaging

- `tools/build_ios_wheel.py --target iphonesimulator` builds all seven extensions
  against the simulator SDK and a matching CPython 3.14 framework.
- Extension filenames and wheel tags identify `iphonesimulator`; device builds
  keep the `iphoneos` suffix. Each platform uses a separate native build directory.
- The scene shader library is compiled for the selected platform and packaged
  with the Python resources. The SDK privacy manifest remains in the wheel.
- The builder rejects a Python.framework whose arm64 slice targets the wrong
  platform. Wheel checks validate the selected Mach-O platform, deployment target,
  exports, Python linkage, resources and RECORD hashes.

The minimum targets remain macOS 14+ and iOS 17+, with standard GIL-enabled
CPython 3.14. Simulator wheels support Apple Silicon Macs. Core ML import and
array helpers still require NumPy compiled for the same runtime platform.
Hardware sensors and device-specific behavior require physical-device checks.

## Validation

Release builds use CPython 3.14.6 on Apple Silicon macOS 26.6.2 and Xcode 27.0.
The macOS regression run completed 351 tests with 162 optional or
environment-dependent cases skipped. Device and simulator artifact checks each
passed all four tests, including shader target inspection and framework mismatch
rejection. macOS binaries target macOS 14.0; both iOS variants target iOS 17.0.
The source archive includes the build helper, native sources and shader source.

Simulator runtime behavior has not been validated for this release. Import,
rendering and device-specific behavior still require host testing. In particular,
a host must supply simulator NumPy before importing Core ML or using array helpers.
